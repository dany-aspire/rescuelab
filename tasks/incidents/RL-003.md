# RL-003 Customer Ticket

## Title

Database is healthy, but the API never becomes healthy with the production Compose overlay

## Customer report

The base Compose stack previously worked. After deployment-specific settings were moved into `compose.production.yaml`, PostgreSQL still starts and reports healthy, but the API never becomes healthy and the web service cannot start normally.

The database already contains customer incident records and its existing Docker volume must be preserved.

## Reproduction

1. Work from `incident/rl-003`.
2. If the worktree has no local `.env`, copy `.env.example` to the ignored local `.env`.
3. Reuse the existing Compose project and PostgreSQL volume.
4. Validate and start the combined production configuration:
   `docker compose -p rescuelab -f compose.yaml -f compose.production.yaml ...`
5. Inspect service state, health checks, API/database logs, resolved configuration, and safe network metadata.
6. Confirm whether PostgreSQL itself is healthy and whether existing data remains present.

## Expected behaviour

- PostgreSQL becomes healthy.
- The API connects to PostgreSQL and becomes healthy.
- Nginx starts after the API is healthy.
- <http://localhost:8080/api/health> returns HTTP 200 JSON.
- Existing incidents load and a new incident persists after browser refresh.

## Constraints

- Diagnose from current runtime evidence, resolved configuration, service health, and documented requirements.
- Do not compare against `main` or inspect the scenario-creation diff.
- Do not delete, reset, or reinitialize the PostgreSQL volume.
- Do not expose credential values in logs or committed documentation.
- Do not change application or configuration files before repair approval.

## Acceptance criteria after approval

- The production overlay preserves valid API-to-PostgreSQL service discovery.
- Database and API connection settings remain explicit and documented.
- Missing required configuration still fails clearly.
- No secret is committed.
- Backend tests and frontend production build pass.
- Combined Compose validation passes.
- The complete production-overlay stack starts without deleting the database volume.
- API health returns HTTP 200 JSON.
- Existing incidents load.
- Browser incident creation and refresh persistence pass.
- Diagnosis and verification are documented in the required artifacts.
