# RL-006 Customer Ticket

## Title

Nginx serves the application, but proxied API paths return not found

## Customer report

The database and API containers are healthy, and the static web application loads through Nginx. However, the UI reports a degraded service and cannot load incidents. Requests made directly to the API container succeed, while the corresponding requests through <http://localhost:8080/api/> return not-found responses.

This began after the Nginx upstream configuration was simplified. Existing PostgreSQL data must be preserved.

## Reproduction

1. Work from `incident/rl-006`.
2. If the worktree has no local `.env`, copy `.env.example` to the ignored local `.env`.
3. Reuse the existing Compose project and PostgreSQL volume.
4. Build and recreate the production-style stack.
5. Confirm container health and the API's direct internal routes.
6. Compare direct API paths with the upstream request URI recorded by Nginx/API when using the external `/api/` route.
7. Inspect Nginx `location` and `proxy_pass` URI semantics.
8. Confirm all existing database records remain intact.

## Expected behaviour

- PostgreSQL and API remain healthy.
- `GET /api/health` through Nginx reaches the API's `/api/health` route.
- Proxied health returns HTTP 200 JSON.
- Existing incidents load.
- A new incident persists after browser refresh.

## Constraints

- Diagnose from current HTTP responses, container health, access/upstream evidence, and Nginx URI mapping semantics.
- Do not compare against `main` or inspect the scenario-creation diff.
- Do not delete or reset PostgreSQL data.
- Do not change application or configuration files before repair approval.
- Do not bypass Nginx in the final verification.

## Acceptance criteria after approval

- External `/api/` paths preserve the API prefix expected by the backend.
- Direct and proxied health both return HTTP 200 JSON.
- Backend tests and frontend production build pass.
- Compose validation and web-image build pass.
- The complete stack starts without deleting the database volume.
- Existing incidents load.
- Browser incident creation and refresh persistence pass.
- Diagnosis and verification are documented in the required artifacts.
