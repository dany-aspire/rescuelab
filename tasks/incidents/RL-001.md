# RL-001 Customer Ticket

## Title

Production page loads, but incident data is unavailable

## Customer report

We rebuilt and restarted the application with Docker Compose. The RescueLab page itself opens at <http://localhost:8080>, but it shows **Service degraded** and the incident queue is empty. Creating an incident does not work.

The containers appear to start. The database and API have reported healthy during initial checks. Calling <http://localhost:8080/api/health> directly returns HTTP 200 with an OK status and says the database is connected.

The problem is reproducible after a production-style frontend rebuild. No database credentials were intentionally changed.

## Reproduction

1. Work from the assigned incident branch.
2. Preserve the existing PostgreSQL volume.
3. Build and start the stack with Docker Compose.
4. Open <http://localhost:8080>.
5. Observe the service badge and incident queue.
6. Try to create an incident.
7. Compare those observations with a direct request to <http://localhost:8080/api/health>.

## Expected behaviour

- The page reports **All systems operational**.
- Existing incidents appear.
- A new incident can be created.
- The incident remains visible after refreshing.

## Constraints

- Diagnose from runtime behaviour, logs, HTTP/browser evidence, and current configuration.
- Do not use a diff against `main` or the incident-creation commit as a shortcut.
- Do not delete or reset the PostgreSQL volume.
- Do not weaken health checks, tests, or error handling.
- Do not change files until the learner approves the evidence-backed diagnosis.

## Acceptance criteria after approval

- Backend tests pass.
- Frontend production build passes.
- `docker compose config` passes.
- The complete stack starts successfully.
- The proxied health endpoint returns HTTP 200 and valid JSON.
- The production browser UI becomes operational.
- Incident listing, creation, and refresh persistence work.
- The diagnosis, smallest safe fix, and verification evidence are recorded in `docs/incidents/RL-001-report.md`.
