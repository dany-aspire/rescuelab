# RL-004 Customer Ticket

## Title

Production web image no longer builds after Docker cache optimization

## Customer report

The application runs in local development, and backend tests still pass, but a clean production Docker Compose build now fails while building the web image. This began after the frontend Dockerfile steps were reorganized to improve dependency-layer caching.

No application feature change was intended. Existing PostgreSQL data must remain untouched.

## Reproduction

1. Work from `incident/rl-004`.
2. Preserve the existing Docker volume and running data.
3. Run the normal repository checks outside Docker.
4. Validate the Compose configuration.
5. Rebuild the web image without cache and capture the earliest meaningful build error:
   `docker compose -p rescuelab build --no-cache web`
6. Inspect the frontend build script, Docker build context, stage filesystem, and Dockerfile instruction order.

## Expected behaviour

- The frontend production build passes locally.
- A clean web Docker image build succeeds.
- The complete production-style Compose stack starts.
- PostgreSQL and API become healthy.
- The browser application loads existing incidents and persists a newly created incident after refresh.

## Constraints

- Diagnose from current build output, Dockerfile stages, build context, scripts, and safe filesystem inspection.
- Do not compare against `main` or inspect the scenario-creation diff.
- Do not delete or reset PostgreSQL data.
- Do not weaken or skip the production build.
- Do not change application or configuration files before repair approval.

## Acceptance criteria after approval

- The frontend build runs only after all required build inputs are present.
- Dependency-layer caching remains sensible.
- Backend tests and local frontend production build pass.
- Compose validation and a clean web-image build pass.
- The complete stack starts without deleting the database volume.
- API health returns HTTP 200 JSON.
- Existing incidents load.
- Browser incident creation and refresh persistence pass.
- Diagnosis and verification are documented in the required artifacts.
