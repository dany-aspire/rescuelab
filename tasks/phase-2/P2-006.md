# P2-006 — Diagnosis-to-Delivery Playbook

## Objective

Create a concise, client-usable playbook for taking an accepted small-app
deployment request from intake through evidence-based diagnosis, approved repair,
verification, delivery, and closure.

## Execution

- Actor: `CODEX_EXECUTOR`
- Surface: `CODEX_CLOUD`
- Branch: `phase-2/p2-006`
- Primary deliverables: `docs/delivery-playbook.md` and `templates/delivery-report.md`

## Required work

1. Define stages for scope confirmation, safe reproduction, evidence collection,
   diagnosis, smallest-fix proposal, explicit repair approval, implementation,
   regression/runtime verification, rollback decision, delivery, and closure.
2. Define the evidence and client-visible output required at each stage.
3. Separate observation, inference, proposed change, completed change, and verified result.
4. Preserve least privilege, secret redaction, backup, rollback, data protection,
   and escalation boundaries from P2-005.
5. Include stop conditions for unclear ownership, insufficient evidence, unsafe
   access, unavailable rollback, destructive data risk, or out-of-scope security,
   payment, regulated-data, and critical-infrastructure work.
6. Define change-scope control so additional defects or requests require a new
   estimate/approval rather than silent expansion.
7. Provide a reusable delivery report covering symptom, evidence, diagnosis,
   approved repair, changed files/settings, verification, data preservation,
   limitations, rollback, and follow-up.
8. Use plain client-facing language; avoid CHATGPT_WORK, CODEX_EXECUTOR, cfgh,
   internal sequence numbers, or marketplace/pricing/proposal strategy.
9. Do not change application code, README, or historical incident artifacts.

## Verification

- Confirm every repair stage requires specific approval.
- Confirm verification distinguishes passed, failed, skipped, and unavailable checks.
- Confirm no example claims unperformed work or unsupported outcomes.
- Confirm no credential, personal path, private marketplace detail, or excessive-access request appears.
- Run `git diff --check`.
