# P2-005 — Client Intake and Triage Kit

## Objective

Create a reusable, portfolio-safe intake and triage kit for small AI-generated
web-application deployment rescue requests.

## Execution

- Actor: `CODEX_EXECUTOR`
- Surface: `CODEX_CLOUD`
- Branch: `phase-2/p2-005`
- Primary deliverables: `docs/client-intake.md` and `templates/client-intake.md`

## Required work

1. Create a plain-language client questionnaire covering symptoms, expected
   behavior, reproduction steps, deployment target, architecture, logs, recent
   changes, urgency, data importance, and previous repair attempts.
2. Define the minimum access and evidence needed for diagnosis while preferring
   least privilege and read-only access first.
3. Include explicit secret-redaction rules: never paste passwords, API keys,
   tokens, private keys, production database dumps, or regulated personal data.
4. Include backup, rollback, database-volume, and approval questions before any repair.
5. Add a triage classification for supported small-app deployment work, work
   requiring clarification, and work that must be declined or escalated.
6. Escalate security incidents, payment systems, regulated data, critical
   infrastructure, destructive recovery, unclear ownership, and unsafe access requests.
7. Provide a compact copyable intake template a real prospective client can fill in.
8. Keep pricing, marketplace strategy, proposals, and private freelance operations out of RescueLab.
9. Do not change application code, README, or historical incident artifacts.

## Verification

- Confirm every requested field has a clear diagnostic purpose.
- Confirm no example contains a real credential, personal path, or private marketplace detail.
- Confirm supported/unsupported boundaries match `docs/PHASE-2.md` and `README.md`.
- Confirm instructions do not request excessive or unsafe access.
